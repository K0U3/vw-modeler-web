# VW 自動モデリング Web ツール

意匠図DXFをアップロードすると、Vectorworks用の3Dモデリングスクリプトを自動生成する社内ツール。

## セットアップ（初回のみ・各自のMacで）

1. このリポジトリをダウンロード（Code > Download ZIP でも `git clone` でもOK）
2. ターミナルで:

```bash
cd vw-modeler-web/backend
python3 -m pip install -r requirements.txt
```

## 使い方

1. **`起動.command` をダブルクリック**（またはターミナルで `python3 -m uvicorn main:app --port 8000`）
2. ブラウザで <http://localhost:8000> を開く
3. 意匠図DXF（VWから「取り出す > DXF/DWG」で書き出したもの）をドラッグ＆ドロップ
4. 天井高を確認（空欄=図面のCH注記から自動検出）し、家具の配置を選んで「スクリプトを生成」（標準は「図面の位置に配置」）
5. 生成されたスクリプトをコピーし、VWの **ツール > ツールマクロ > 新規(Python)** に貼り付けて実行

※ MUJI家具のシンボル自動配置を使う場合は、詳細設定の「家具ライブラリVWX」を自分のMacのMUJI家具VWXのパスに変更（無い場合は未配置として報告します）

## 家具を室内に配置する

- 「家具の配置」＝**図面の位置に配置**で、DXFから読み取った家具をモデル内に配置します。従来の手動配置用の出力は「モデルの右横に整列」を選べます。
- 対象は家具レイヤー（標準は「家具」「家具01」等）のブロックや輪郭です。別名のレイヤーは「家具の詳細設定」で指定してください。家具が描かれていない図面へのレイアウト提案は行いません。
- カタログ照合できた家具はMUJIライブラリから取り込みます。ベッド・ソファもMUJI部品を優先し、照合・取り込みができない家具は未配置です。
- 結果に配置先・家具と設備の合計・ベッド・ソファ・未配置件数を表示します。ライブラリ照合数は取り込み候補数で、実際の取り込み結果はVW実行時に確認します。
- 生成後の「家具の照合・調整」で元図面の名称・外形寸法・座標と選定部品を確認できます。部品の変更、角度、X/Y移動、配置しない設定はコピー・ダウンロードに反映されます。家具番号はVWモデルの「家具n」に対応します。
- 図面位置を保持し、壁との干渉は警告にします。寸法だけでは種類・正面・左右勝手を確定できないため「要確認」と表示します。ライブラリの実測外形と公称寸法にも差があるので、緑のガイド枠とVWで照合してください。
- APIの `furniture_mode` は `plan`（標準）または `lineup`。指定を省略した次の生成で、前回の整列設定を引き継ぎません。

## チーム外への共有を防ぐ

`共有モードで起動.command` を使うとID/パスワード付きでLAN公開できます（ファイル冒頭のID/PASSWORDを書き換えて使用）。

## クラス（レイヤー）別の立ち上げルール

| クラス | 立ち上げ方 |
|---|---|
| 躯体 | 実頂点ポリラインをそのまま立ち上げ（二重外形は外周4辺帯に変換） |
| 壁・建具 | 壁＝閉ポリを立ち上げ。建具INSERT＝3方枠（両縦枠+上枠の簡易ボリューム）+ 扉パネル（図面の厚み20〜60mmをそのまま押し出し）+ 垂れ壁 |
| インナーサッシ | INSERT位置に共通窓ユニット（幅1500以上=掃き出し / 未満=腰高）。外周帯・内壁はサッシ位置で開口 |
| 断熱 | SOLID/閉ポリをそのまま立ち上げ |
| 天井・点線 | 梁ライン。平行2線はペアで1本に、単線は幅200に展開。**梁下端＝最寄りの「CH≒〇〇」注記**（無ければ天井からBEAM_D下がり） |
| 家具* | カタログ照合 → MUJIライブラリからシンボル自動インポート（該当なしは部品選択まで保留） |

## 窓の個別調整（生成後）

全窓に番号が振られる（`win(番号, 種別, ...)` とスクリプト末尾の窓一覧）。
生成スクリプト冒頭の `WIN_OVERRIDES` に番号をキーに `sill`（腰高）/`head`（まぐさ）等を書いて再実行すると、
前回の生成物を自動で消してから調整後のモデルを作り直す。

```python
WIN_OVERRIDES = {
    3: {'sill': 600, 'head': 2200},   # 窓3だけ腰高600・まぐさ2200に
}
```

## 玄関扉（共通・必ず1箇所）

玄関ラベル最寄りの開き戸ARC（半径550〜1200）を玄関扉と判定し、3方枠＋扉パネル（厚40）＋垂れ壁を立ち上げる。
ラベルが無い図面では最大半径のARCを採用。検出できない場合はダイアログに⚠表示。

## 家具認識の仕組み

1. シンボル名・ブロック名の完全一致を優先。寸法や型番の数字は削除しません。
2. 明示された家具の種類を絞って照合。型番が異なるものや名前の曖昧な候補は自動採用しません。
3. 名前に家具の種類が明示されている場合のみ、実測寸法を各辺±15%以内で照合。無名グループ・輪郭は寸法だけで別種類の家具へ変換せず、部品選択まで保留します。近い候補が複数ある場合は未配置として保留します。
   - 部屋ラベルやベッド標準寸法は候補カテゴリの補助に使用します。
   - 一般レイヤーの家具フットプリントも走査（建物外形が取れた図面のみ）、入れ子輪郭は面積最大のみ採用します。
4. 生成結果の一覧で、保留・寸法候補・外形不一致・壁干渉を確認し、必要ならMUJI部品を選択します。

**家具の配置ルール:**
- 原点補正（OX/OY）を内蔵し、標準モードでは図面位置を保持します。壁干渉による自動移動は行いません。
- INSERTの元の回転角を保持。寸法の縦横入れ替えが必要な候補のみ+90度にします。鏡像INSERTは自動照合を保留します。
- ベッド・ソファもライブラリ部品を使用します。読み込めない場合は配置せず理由を報告します。
- トイレ・キッチン・洗面台の個数を一律1つに制限せず、部屋ラベルだけから設備を追加・移動しません。
- 平面画像だけでシンボル名や高さ、正面を確定することはできません。元のDXFとMUJI家具 v2021の実行環境で最終確認してください。
- 段差マーク（Z形の線）・点線は壁として立ち上げません。

## モデリングのルール

- **天井高に既定値はない**: ユーザー指定 > 図面注記（"天井高2400"・"CH≒2400"・"CH:3670" 等を自動検出、最頻値を採用）> どちらも無ければ処理を止めて入力を求める（CLI は `--ch <mm>`）
- 部屋ラベル検出: トイレ/浴室/洗面所/キッチン/リビング/ダイニングの基本6室をチェックリスト表示（半角カナ・LDK表記対応）
- 躯体は実頂点形状で立ち上げ
- **内壁（間仕切り壁）**: 閉ポリライン壁（`壁・建具` レイヤー等）+ 薄壁(25〜60mm) + 平行LINEペア壁(壁厚50〜350mm) を立ち上げ。建具ARC位置でドア開口を抜き `DOOR_HEAD`〜CH の垂れ壁を生成
- RC躯体の二重外形（外形線+内形線）は外周4辺の壁帯に自動変換。塗り率の高い大型閉ポリ（家具外形等）は充填ブロック化を防ぐため除外してコメント報告
- 西面＝腰壁の連続窓 / 東面＝青線(建具 color=5)位置の FIX 窓 / 南北＝建具位置に腰窓
- **窓は全種共通の `win_unit`**: 枠＝FR見付×FD見込みの縦横角材ボリューム（上下枠・左右縦枠・方立・召し合わせ框）＋ ガラス＝GT厚の薄板ボリューム。引き違いは前後トラックにガラス2枚
- 窓種別ヘルパー: `ribbon_window`(腰壁連続) / `fix_window`(大FIX) / `hikichigai_window`(腰高引き違い) / `hakidashi_window`(掃き出し引き違い) — いずれも腰壁/垂れ壁 + `win_unit` の組み合わせ
- 梁: `梁` レイヤーの線/ポリラインを天井から `BEAM_D` 下げて立ち上げ
- **家具**: `家具*` レイヤー（前方一致）の INSERT/フットプリントをカタログ照合。無名グループ(グループ-N)は部品選択まで保留。生成スクリプトが **MUJI家具ライブラリVWXからシンボルを自動インポート**して配置し、取込不可なら配置せず家具番号・部品名を報告
- 外部階段・建物外は除外

## 家具カタログ（MUJI 等のシンボル集）

現行カタログ: 155件（h=高さ・z0=設置下端・vw_name=VWシンボル実名 付き。150件はACIS 3Dソリッドの実測寸法）。
旧版は `furniture_catalog.v1.backup.json` に保存。

再生成の手順（新しいライブラリを使う場合）:

```bash
cd ~/dev-projects/vw-modeler-web/backend
python3 build_catalog.py "<家具ライブラリ.dxf>"       # → 基本カタログ
# 高さ・実寸の付与は tools/extract_block_z.py → tools/enrich_catalog.py
# （venv + 最新ezdxfが必要。3DSOLIDのACISデータから実測する）
```

- VWシンボル名はDXFブロック名と原則同一（SJIS63バイト超の名前のみ末尾スペース差あり・検証済み）。**vw_name の末尾スペースは絶対に strip しない**
- 間取り図の家具は 名前照合 → 同種家具の寸法照合の順で選定
- 生成スクリプトは `vs.BuildResourceListN(16, ライブラリVWX)` → `vs.ImportResToCurFileN` でシンボルを自動インポート → `vs.Symbol(名前, (x, y), 角度)` で配置（ポイントはタプル形式が公式仕様）
- インポート不可（ライブラリ不在・名前不一致）は未配置として報告
- 照合できない家具はスクリプト末尾にコメントで列挙（手動配置用）

## 実部品のみ配置

家具の簡易ボリューム生成は廃止しました。未特定の家具は照合一覧でMUJI部品を選ぶまで配置しません。取込に失敗した場合も箱を生成せず、VWの完了ダイアログに家具番号・部品名・ライブラリパスを表示します。対象図面とOK例のVWXによる位置・向きの最終照合は別途必要です。


## 図面専用の家具対応表

DXFと併せて、確認済みのJSON対応表を任意で選択できます。同じDXFのSHA-256を持つ対応表のみ受け付け、異なる図面への誤適用を防ぎます。対応表のない家具は従来どおり照合一覧から選択します。

形式は `{"version":1,"dxf_sha256":"...","assignments":{"元のブロック名":[{"symbol":"カタログのvw_name","dx":0,"dy":0,"angle":0}]}}`。`dx`、`dy` は元の平面図の家具中心からの図面XY方向のオフセット(mm)、`angle` は配置の絶対回転角(度)です。ソファや収納などは複数の実部品を指定できます。部品は拡縮せず、配置位置を維持するための原点補正を行います。実寸が平面図と異なる場合は、配置後の干渉を確認してください。

家具対応表に指定できるのは同梱MUJIカタログの部品のみです。対応表はリクエストごとに読み込み、サーバーには保存しません。個別物件の対応表や図面を公開リポジトリに含めないでください。

確認した左右勝手が必要な場合のみ、部品に `"mirror_y":true` を指定できます。回転・中心合わせの後、図面X方向の中心線を軸にY方向を反転します（キャビネットの正面を保ったまま、キッチンのシンクとコンロの位置を入れ替える場合など）。

## Webパースへの移行

完成形は図面アップロードからパース保存までWebで完結し、Vectorworks出力を追加機能にします。[実装方針と未実装部分](docs/web-rendering.md)を参照してください。現時点ではパース生成機能はありません。

確認済みの元DXFには家具対応表を自動適用します。別の図面でも確認済みの詳細な平面形状は名前に依存せず照合します。単純な矩形や競合候補は保留するため、全種類の家具を自動認識するものではありません。
